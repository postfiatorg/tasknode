# NAVCoin registry and selection

The server publishes `/api/l1/navcoin/registry` after login. Each entry identifies one asset by `asset_id` / `nav_asset_id`, with its own route, PFUSDC quote source, current terms and action capabilities. `/api/l1/navcoin/config?asset_id=<id>` returns only that selected entry; a missing or unknown selection returns 404. There is no default coin and no `NAVCOIN_CONFIG_JSON` launcher override.

`server/l1/navcoin-metadata.json` contains registration asset IDs, slugs, editorial names/descriptions/methodology and retirement notices. It cannot set fees, market permissions, profile, supply, NAV, route or quote source. Adding a metadata entry only displays it if its exact asset has an active profile on the configured chain. Tickers are not identity: the mainnet-linked uppercase A666 and the historical lowercase a666 test asset are different assets.

The server uses the configured loopback `L1_HISTORY_RPC_URL` to read status, profiles, asset information, route registry/supply status, source settlement custody and both directions of each governed quote-source order book. Reads are sequential, cached for 15 seconds and shared across requests. A changed chain tip or mismatched asset/route/book identity rejects the read. No signer is exposed. The gallery uses this public snapshot; review and submission independently refresh relevant state and require wallet quotes, signatures, literal acceptance and verified effects.

Book trading is available for six-decimal, non-retired assets with an observed source-asset order book or a valid native creation route that can establish that market. An empty book does not promise a fill. Native creation/cash-in require matching finalized policy NAV, live/unpaused route, valid height/freshness, supported source custody and no external spread recipient. Amounts, wallet inventory, receiving limits and reserve capacity are checked during review. Unsupported or stale entries show the chain-derived reason, with no transaction buttons. A changed selection remounts the action screen so a previous coin's review cannot be signed under the new selection.

Native creation reserves source PFUSDC, subscribes, then releases the unused export entitlement. Each step is separately reviewed and signed. The required unused Ethereum recipient binding comes from that coin's registered route controller; this flow never exports or signs an Ethereum transaction. Cash-in is limited to the wallet's tracked subscription inventory and matching source reserve. Order-book acquisitions do not create subscription eligibility. Fees remain outside NAV as verified by actual source custody and supply deltas.

Ethereum capability currently reports the native route's registered token/controller and chain ID, with liquidity explicitly unverified. Registered addresses are not proof of deployment or usable pool liquidity. No Ethereum swap action is enabled by a metadata flag or predicted address.

The consumer entry point is NAVCoins. Its Buy and Cash in links select that asset; Market and Cash in also have a coin selector. Home values each held NAVCoin from its own finalized reading and excludes retired NAV from its total. Activity labels every registered asset and route by ID.
